# 时光册 · SHIGUANGCE

把一组照片，做成一本可以翻阅、编辑和装饰的**数字纪念册 / 旅行手账**。

不是照片墙，不是相册 App，也不是 Canva 的复制品。产品的目标只有一句话：

> 「我不是在编辑一个网页，我是在制作一本属于我的回忆。」

## 技术栈与关键取舍

| 领域 | 选择 | 理由 |
| --- | --- | --- |
| 构建 | Vite 6 + React 18 + TypeScript | 启动快、生态稳定；刻意不用 React 19，避免无谓风险 |
| 样式 | Tailwind CSS 3 | 设计 token 集中在 `tailwind.config.js` + `src/lib/designTokens.ts` |
| 状态 | Zustand 5 | 编辑器需要「一个集中的、可快照的文档树」，Zustand 比 Context 更适合高频更新 |
| 编辑器渲染 | **DOM + CSS transform，而非 Canvas** | 见下方说明 |
| 动画 | 原生 CSS / Web Animations | 没有引入 Framer Motion：翻页与微交互用原生实现已经足够，少一个依赖 |
| 拖拽 | 自研指针事件 | 见下方说明 |
| 持久化 | IndexedDB（经适配器抽象） | 照片二进制与纪念册数据都留在本机，离线可用 |

### 为什么编辑器用 DOM 而不是 Canvas

纪念册的内容是**照片、文字、便签、贴纸**。这些元素：

- 需要保持矢量级清晰（缩放画布时文字不能糊）；
- 需要能直接使用 CSS 字体、文字排版、阴影、混合模式；
- 需要可访问、可选中、可用输入法直接编辑中文；
- 需要能以 JSON 形式无损序列化（这决定了「未来能否轻松迁移到 S3 / 数据库」）。

Canvas 方案需要自己实现文字排版、字体加载、输入法处理，且在 Retina 下还要处理
devicePixelRatio —— 收益远小于代价。因此选择 DOM，并配合一套**与屏幕无关的坐标系**：

```
数据里存的是「页面坐标系」（720 × 900）中的 left/top/width/height
屏幕渲染 = 外层 transform: scale(zoom)
因此同一份数据在 1440×900 / 1920×1080 / 2560×1440 下完全一致，
元素尺寸、字号、相框比例都不会随缩放漂移。
```

### 为什么自己写拖拽/缩放/旋转

`src/lib/interaction.ts` 是纯计算的几何引擎，与 React 完全解耦：

- **可单元测试**：旋转元素的缩放锚点、吸附阈值、多选层级这类最容易错、
  又最难靠肉眼发现的问题，全部由 `pnpm test` 覆盖（33 个用例）。
- **行为可控**：需要支持旋转元素的正确缩放、Alt 拖拽复制、
  拖拽时对齐吸附、跨页拖拽，这些在通用拖拽库里反而要绕开它的假设。

> 这套测试实际抓到了几个真实缺陷：`anchorFor` 返回了被拖动的角而不是对角
> （导致每次缩放元素都会整体漂移）、一处在缩放时跳变的 keepAspect 实现，
> 以及**旋转元素缩放**：`computeResize` 曾把「旋转后的轴对齐包围盒」
> 当成元素自己的矩形用，于是指针一动不动、旋转 90° 的 200×100 元素
> 也会变成 150×150、锚点漂 50px；拖左右边手柄还会改高度。
> 现在的实现先把 AABB 还原成**元素本地矩形**，在本地坐标系里做缩放，
> 再把新中心经 `anchor + rotate(C − anchor, θ)` 映射回世界坐标：
> 指针不动时几何零变化，拖动点跟随误差 < 0.1px，锚点漂移 < 0.1px
> （对 0°/17°/30°/45°/90°/137°/180°/270° 与 8 个手柄全组合断言）。

## 数据模型

核心思想：**几何值全部存在页面坐标系里；元素内容放进可辨识联合**，
这样新增元素类型不需要修改编辑器核心。

```ts
Album {
  id, title, subtitle, theme, coverPhotoId,
  startDate, endDate, location, route,
  pages: Page[],
  photoIds: ID[],                    // 只为「素材库 ↔ 纪念册」建立反向索引
  pageSize: { width, height },        // 页面坐标系尺寸，默认 720 × 900
  share: { enabled, slug, updatedAt },
  createdAt, updatedAt
}

Page {
  id, title, role: 'cover' | 'content' | 'ending',
  background: { color, paper, lineColor, vignette },
  elements: AlbumElement[],           // 数组顺序 = 图层顺序，最后一项在最上层
  date?, location?, memo?
}

ElementBase {                         // 所有元素共享
  id, kind, x, y, width, height,
  rotation, opacity, locked, radius?, shadow?
}

PhotoElement   { kind: 'photo',   data: { photoId, style, fit, caption, focusX/Y … } }
TextElement    { kind: 'text',    data: { text, preset, fontFamily, fontSize … } }
StickerElement { kind: 'sticker', data: { glyph | svgId, category, tint } }
NoteElement    { kind: 'note',    data: { text, variant, background … } }
StampElement   { kind: 'stamp',   data: { text, subText, shape, color, distress } }
DateElement    { kind: 'date',    data: { date, endDate, format } }
MapElement     { kind: 'map',     data: { points, ink, accent } }
ShapeElement   { kind: 'shape',   data: { shape, fill, stroke, strokeWidth } }

PhotoAsset {                          // 照片「引用」，不含二进制
  id, url, storageKey?, source: 'demo' | 'local' | 'remote',
  width, height, takenAt?, location?
}
```

**关键点**：`PhotoAsset` 只是指针。照片二进制单独存放，
`storageKey` 指向 IndexedDB（现在）或 S3 object key（未来）。
因此纪念册 JSON 很小，可以随时整体迁移。

## 编辑器架构

```
EditorTopBar       返回 / 册名 / 页码 / 撤销重做 / 缩放 / 预览 / 保存 / 分享
─────────────────────────────────────────────────────────────
导轨 │ 左侧面板           中央跨页画布              │ 右侧属性面板
     │ 插入 / 照片 /       左侧页 + 书脊 + 右侧页     │ 位置大小 / 旋转
     │ 贴纸 / 页面 / 模板   元素交互层 / 吸附辅助线    │ 层级 / 类型专属属性
─────────────────────────────────────────────────────────────
PageStrip          页面缩略图：切换 / 拖拽排序 / 复制 / 删除 / 新增
```

### 撤销 / 重做

采用**文档快照 + 结构共享**，而不是为每个操作写一个反向命令：

- `commit(label, mutator)`：目标操作在草稿上整体执行，把「变更前」的相册压入历史栈；
- `beginTransaction()` / `commitTransaction(label)`：拖拽、输入这类高频操作
  在开始时打一个快照，结束时才入栈 —— 因此一次拖拽 = **一步**撤销，而不是上百步。
  属性面板里的滑块与文本输入也走这条路径：第一次改动开事务，450ms 静默
  或指针抬起就提交，一整段调整只留一条历史；
- 历史同时记录**选择状态**，撤销后选中项会回到当时的状态；
- **草稿的所有权属于编辑器**：存档只在「打开某一本册子」时流入一次，
  之后由自动保存单向写回。`libraryStore` 里那一本被替换引用**不会**触发重新载入 ——
  否则每次自动保存落地都会清空撤销栈、清空选中并把画布拨回第 1 页
  （这正是之前「编辑约 900ms 后撤销按钮突然变灰」的原因）。

### 交互细节

- 拖拽吸附到页面中线 / 页边 / 其它元素的边与中线，显示洋红辅助线；按住 Alt 临时关闭；
- 选中元素按住 Alt 拖拽 = 复制一份留在原处；
- 缩放手柄支持旋转后的元素（指针反向旋转回本地坐标系），Shift 保持比例，Alt 从中心缩放；
- 拖到另一页上时提示「放开即可移到右页」，松手即完成跨页移动；
- 双击文字 / 便签 / 印章可直接原位编辑（Cmd/Ctrl+Enter 提交，Esc 取消）；
- 快捷键：`Ctrl+Z` / `Ctrl+Shift+Z` / `Ctrl+S` / `Ctrl+A` / `Ctrl+C·X·V` /
  `Ctrl+D` / `Delete` / `方向键微调` / `Shift+方向键 10px` / `[` `]` 调层级。

### 自动保存

编辑器持有草稿副本，任何改动后 **900ms 防抖**写回书架 + IndexedDB，
顶部常驻显示「保存中 / 已保存 hh:mm」。离开页面前会 `flush()` 未落盘的改动。

## 页面材质：纸板模型

**核心视觉模型：页面是载体，照片 / 文字 / 贴纸只是「贴在纸板上的内容」。**

```
一本厚纸纪念册
├── 纸板 1 ── 正面纸面 + 贴在上面的照片/文字/贴纸（+ 背面纸面 + 四周切边）
├── 纸板 2 ── 同上
└── ...
```

一页**不是**「照片外面套一层白纸」。它是一块完整、独立、有厚度的硬质纸板，
尺寸由页面决定，绝不会随照片大小变形。层级永远是：

```
页面（纸板正面）  ← 载体
  └── 照片 / 文字 / 贴纸 / 便签  ← 内容，贴在纸面上
```

### 厚度是怎么做出来的

`src/components/book/BookPage.tsx` 把纸板做成一个**真正的长方体**（CSS 3D）：

- **正面** `translateZ(0)`：纸面 + 内容
- **背面** `translateZ(-thickness)`：纸板另一面的纸
- **四个侧面**：与页面同尺寸的矩形绕对应边 `rotateX/Y(±90deg)` 撑起厚度
  - **书口（外缘）**用细密横向纹路表现「一叠纸的切边」
  - **书脊侧**纹路更疏、颜色更深
  - 侧面都带 `backface-visibility: hidden`：纸板转到某个角度时，
    朝向观察者的那一面自动显示、背离的自动隐藏 —— 翻页过程中
    先看到书口，越过 90° 后换成书脊侧，不需要任何额外判断

纸板厚度 = 页面高度 × 1.1%（720×900 坐标系下约 10px）。

### 页面叠层：书口**不放**任何凸出物

书口外侧（左页左外缘、右页右外缘）最终选择了**什么都不画** ——
左右页与书脊、封面完全齐平，书口没有任何多余形状，也就没有任何会在翻页时动的东西。

这里先后试过两种实现，都被去掉了，原因值得记下来：

| 实现 | 问题 |
| --- | --- |
| `layers` 个互相错开 `step` 的 `div`（阶梯） | 最外沿比页面多伸出 **21 页px（≈16 屏幕px）** —— 「每一页都不是齐的、右边有凸出来的地方」 |
| 一条平直的厚边（`ForeEdgeDeck`） | 平直了，但仍凸出 16 页px；而且厚度只能跟着「还剩多少页」走，翻页时必然变化，是一处需要额外维护、又永远和页面本体争夺注意力的装饰 |

书的厚度已经由**纸板侧面**（`BookPage` 的四个 `EdgeFace`）和封面装帧边表达得很清楚，
不需要再靠书口外侧堆东西来暗示。

验收（`pnpm flip:verify`）：**统计所有「超出所在页面盒子」的纸块类元素，必须为 0**
（早期版本查的是一个叫 `data-stack` 的属性，而全项目根本没有生产者，
那条断言恒为真、等于没有），且左页左缘、右页右缘必须正好落在跨页容器的
两条边上（偏差 < 0.5px）。

### 中缝：书脊只能是「折痕 + 缝」，不能是第三张纸

**左页是一张完整的纸，右页也是。** 中缝只是两张纸向书脊里陷进去的地方。
一旦它看起来像「另一张纸 / 一个独立叠加的 DOM 层」，整本书就假了。

这里踩过一次很大的坑，结构值得写清楚。早先中缝由三层**几何互不相干**的东西叠成：

```
① 跨页书脊层   left = W-30, width = 74, z-index 50   ← 独立 DOM，压在两页之上
② 页面内装订暗部 每页 inset w-16（页面左右各 64 页px 的渐变）
③ 装订缝黑线    left = W + GAP/2 - 0.75, width = 1.5, z-index 50
```

其中 ① 是元凶。它是一条**跨在两页之上、压在纸叶之上**的整页高渐变，
不属于任何一张纸：既不跟随左页也不跟随右页，翻页时它一动不动地浮在书上。
而且它左右不对称（30px 压左页、44px 压右页），最深的那条暗带落在
**右页正文起始处**而不是折痕上。三层叠起来，中缝就成了一段
「宽约 56 屏幕px、跨越两张纸边界、由灰白到深黑再到灰白」的独立竖带 ——
看上去就是一张夹在左右页之间的纸。

现在书脊由三样东西构成，**每一样都归属明确**：

| 构成 | 归属 | 位置 |
| --- | --- | --- |
| `PageFoldShade`（每页内缘的折痕，34 页px） | **页面自己的矩形内部** | 左页贴右边、右页贴左边，`z-index 30` |
| `[data-gutter]`（两页之间的缝） | 跨页容器，画在**页面之下** | 只占缝隙 + 极小外扩，`z-index 1` |
| 纸叶抬起时的动态阴影 | 各自页面的容器内 | 随进度增强/收敛 |

关键性质：

- **折痕长在页面上**，所以纸张到哪里结束、折痕就在哪里结束；
  翻页时它跟着纸叶一起走，不会变成一块与运动无关的浮层；
- 中缝不再有「压在纸叶之上」的元素（验收脚本从「书脊 z > 纸叶 z」
  改成了相反的一条：`[data-gutter]` / `[data-fold]` 都不得高于纸叶层）；
- 实测（`y=500` 横扫一行像素）：左页内缘 236 → 156 单调压暗、缝里 9 左右、
  右页内缘 148 → 240 单调变亮，左右基本对称，整条缝只有 **10 屏幕px** 宽。

## 翻页：状态机与纸板运动

代码里真正存在的状态只有两个：`flip === null`（静止）与 `flip !== null`
（纸叶挂在书上，全部视觉由 `progress ∈ [0,1]` 驱动）。README 早先写的
`IDLE → FLIPPING → ANIMATION → COMMIT → IDLE` 只是概念叙述，`FlipState.phase`
字段曾经只写不读，已经删掉。

**只有动画结束后才提交逻辑页号。** 整个动画期间 `album` 与 `spreadIndex`
都不变，动画中的 DOM 因此不会被状态更新打断。

翻动中的是一块真正的**双面厚纸板**：正面 = 正在翻走的那一页，
背面 = 翻过来之后朝上的那一页，绕书脊 0 → 180°。
缓动 `easePageTurn`（`easeInOutCubic`）外包一层 `easeSettle`，900ms，
`t = 1` 处导数为 0，让纸「贴」到位而不是砸到位。

### 七个关键修复

**1. 「页还没落下，另一边已经换画面」。**

翻页时静止层（纸叶下面）两侧各显示什么，取决于一个容易被忽略的几何事实：
**纸叶只有转过 90°（立起来）之后才会覆盖到落点那一侧**；
在那之前落点侧的纸面是露在外面的。所以两种做法都是错的：

- 一开始就把落点侧换成目标页 → 用户立刻看到「另一边已经换画面」
- 全程保持不动 → 纸叶落地卸下时内容突变，就是「翻完闪一下」

一开始的解法是「以 0.5 为界切换」，但它只是把突变挪到了 90° 那一帧，
**用户仍然能看到自己正在读的那一页变画面**。真正的解法是：
把「换页」这件事交给纸叶自己 —— 静止层根本不切换。

```
向后翻（next，右页翻到左边）：
  纸叶正面 = from[1]（被抬走的那一页，翻页起点的右页）
  纸叶背面 = to[0]  （翻过来朝上的那一页，落地后的左页）
  静止左槽 = from[0]，翻页过程**全程不变**（这是你正在读的页）
  静止右槽 = to[1]，翻页起点就已换成新右页（纸叶一抬起就露出它）

向前翻（prev，左页翻到右边）：对称处理
```

一句话：**被纸叶抬走的那一侧，起点就被纸叶盖住，可以换成新页；
被纸叶落下的那一侧，必须全程保持旧页，落地那帧才换。**

于是正在阅读的那一页在整个动画期间**一个像素都不变**，
落点侧则在纸叶盖上去的瞬间由 commit 换页，交接完全不可见。

验收（像素层面，不靠肉眼）：在 `next` 与 `prev` 各自的
`progress = 0.15 / 0.35 / 0.5 / 0.7 / 0.9 / 0.99` 六帧上抓取静止层内容，
**正在阅读的那一页必须六帧完全相同**（实测差异 0.23%，且全部集中在书脊边缘
—— 那是纸叶抬起时投下的阴影，属于正确行为），
而落点侧自始至终显示目标页。

**2. 纸叶与书本不能共享 3D 排序上下文。**

若两者处在同一个 `preserve-3d` 里，浏览器会按**三维位置**排序：
纸叶转到一半时，远离书脊的那一半在 Z 轴上位于静止页之后，
于是被判成「在下面」而被盖住 —— 整个纸板凭空消失（90° 那一帧最明显，
而那正是纸叠侧边最该被看到的时候）。解法是让两者各自拥有独立的
`perspective` 容器（互为兄弟节点），前后关系改由 `z-index` 决定。

**3. 纸板背面不要做任何额外镜像。**

背面只需一次 `rotateY(180deg)`：它既让这一面朝向纸板背面，又把内容翻正。
再加一次 `rotateY(180deg)` 或 `scaleX(-1)` 都会**翻回去**变成左右镜像
（实测照片与文字的左右顺序会整体对调）。
`translateZ` 的厚度位移必须单独一层，否则会被旋转带着走，
正反面就不在同一条法线上。

**4. 落地那一帧必须**就是**提交后的那一帧。**

这里叠了两个独立的问题。

**(a) 动画跑完时 `progress` 真的停在 1 吗？没有。**
`requestAnimationFrame` 以 60fps 推进，最后一帧的 `t` 几乎不可能正好等于 1，
纸板实际落在 **≈179°**。若此时直接 commit，画面会从 179° 硬跳到 180° 平铺。
解法是在 commit 之前**多渲染一帧精确终态**：

```
t 到达 1 → settleThenCommit()  渲染一帧 progress = 1（纸板正好平放）
         → 下一帧才真正提交页号，并卸载纸叶
```

`settleThenClear` 同理，用于回弹（progress 回到 0）的收尾。

**(b) 光「角度对了」还不够 —— 落平帧与提交后的静止帧必须是同一棵 DOM。**

曾经的写法是让**纸叶背面**在落平帧平铺出来充当静止页（并去掉 3D 变换以保住
文字亚像素抗锯齿）。内容与位置都对，但它有两个藏不住的问题：

- 它仍然是**挂在最上层的纸叶**（`z-index: 40`），会盖住书脊与装订缝；
  而提交后纸叶被卸下，这两者又回到纸面之上 —— 纸叶消失的一瞬间，
  页面内侧的压盖关系变了。
- 「书口纸块厚度」是按**当前页号**算的。落平帧里静止层左页还是旧页，
  提交后才是新页 —— 于是纸块在纸叶消失的瞬间突然增减两三层
  （实测外沿缩回 8.4 页px ≈ 6.3 屏幕px）。这条路后来被整体删掉（见上一节）。

两者叠起来，就是「页落下后会动一下」。

现在的做法分两步：

1. **落平帧不再渲染纸叶**，直接按提交后的那一屏渲染静止页
   （`landedLeft` / `landedRight`）。于是落平帧与下一帧是同一棵 DOM、
   同一套层叠关系：书脊压盖、装订缝位置完全一致。
2. **书口不再有任何凸出物**（见上一节），所以也不存在「厚度在落地时跳变」。

验收（`pnpm flip:verify`，走 Chrome DevTools Protocol）：要求
**落平帧的左右页几何与目标跨页静止态逐值相等**。
实测 `[244.56, 86, 539.2, 674]` vs `[244.56, 86, 539.2, 674]` —— x / y / 宽 / 高
四位全部相同，跨页容器也相同。

> 这个脚本顺手排掉了一个**验收陷阱**：`BookViewport` 的尺寸带 0.4s 过渡
> （`scale` 初值 0.6 → 实测 fitScale），而外层用 `items-center` 居中 ——
> 容器还在过渡时，书本的垂直位置本来就在动。最初的脚本「BookSpread 一出现就读」，
> 读到的是过渡中间态，两次读数页面 y 差出 64px，看上去像真的在动。
> 所以脚本现在要求**连续两次采样（间隔 250ms）几何完全一致**才认账。

**5. 旋转轴必须在装订缝的正中。**

这条最隐蔽，因为它只在动画**接近结束**时才明显起来。

跨页布局是 `[左页][GAP][右页]`（`GAP = BOOK_GAP = 14`）。
绕 `x = h` 转 180° 会把 `x` 映射成 `2h − x`，于是纸叶盒体 `[W+GAP, 2W+GAP]`
落到 `[2h−2W−GAP, 2h−W−GAP]`。要让它正好等于左页 `[0, W]`，解得：

```
h = W + GAP / 2        ← 缝隙正中（物理上就是书脊所在的位置）
```

早先取的是**右页左边缘**（`h = W + GAP`，也就是 `transformOrigin: 'left center'`），
纸叶落地时会落在 `[GAP, W+GAP]` —— **整整偏右一个缝宽**。连锁现象恰好是：

- 翻页途中纸叶盖住了中间的缝隙 → 「书中间没有空隙」
- 落平后真实页面就位、缝隙回来 → 「翻完又有空隙了」
- 纸叶上的内容比最终页面偏右 14px → 提交那一刻整页向左跳 → 「页面会移动」

而且这个偏差在 0° 时是 0、在 180° 时最大，所以它看起来不像「一开始就错位」，
而像「越翻越不对、翻完才跳一下」，很容易被误判成别的原因（比如抗锯齿或时序）。

验收：量**纸叶背面**在 `p = 0.99` 时的位置。这里有个关键区别：

- **书脊侧**那条边正好在旋转轴上，`Z ≈ 0`，透视不产生缩放 ——
  它的位置由旋转轴唯一决定，所以卡到 **2px**（轴取错会差约 10.5px = `14 × 缩放`）
- **书口侧**那条边离观察者最近，被 `perspective(3400)` 放大
  `d/(d−z) ≈ 1.0067`，实测外推 3.4px。这是**正确的透视**、不是 bug，
  而且 `t → 1` 时会收敛到 0，所以放宽到 6px

> 这个 bug 能藏那么久，是因为「落平帧 vs 静止态」这条断言**看不见它**：
> 落平帧是直接渲染静止页的，根本不含纸叶。必须单独量纸叶本身。
> 而且断言写完还要**故意把 bug 放回去跑一遍**，确认它真的会红 ——
> 实测旧轴报出「书脊侧偏差 10.48px」，正好是 `14 × 0.74889`。

**6. 缓动曲线的尾段必须真的减速（否则落地最后一帧会平移约 6px）。**

这条是第 4、5 条都修好之后才浮出来的 —— 前面那些是「帧内交接」，这条是「帧间步长」。

`requestAnimationFrame` 按 60fps 推进，900ms 的动画最后一帧只能走到
`t ≈ 53/54 ≈ 0.981`，也就是纸板约 **176.6°**。若缓动曲线在 `t = 1` 处的导数不是 0，
这最后 3.4° 就会在一帧（16ms）里走完；而纸叶此时仍略微倾斜，书口侧那条边离观察者
最近、被 `perspective` 放大约 1.4% —— 于是**一帧内书口侧边缘平移约 6px**。
看起来就是「页一落下就动一下」。

而旧曲线 `0.16·t³ + 0.56·t + 0.28·(1−(1−t)^3.6)` **两端都不减速**，
和它自己注释里写的「起手轻推（慢）… 接近落下时减速」正好相反：

| | t = 0 | t = 0.5 | t = 1 |
| --- | --- | --- | --- |
| 旧曲线导数 | 1.57 | 0.76 | **1.04** |
| `easeInOutCubic` | 0 | 3.0 | **0** |

换成首尾导数为 0 的 S 曲线后，最后一帧的进度已经到 **0.99997（≈179.99°）**，
那一步降到 0.01px 级别；顺带起手也更像「把纸捏起来」而不是被弹了一下。

验收：量 `?sampleAt=53`（真实动画的最后一帧）时**纸叶背面在书口侧的边缘**，
与落平帧的位置之差必须 < 1px。旧缓动实测 **6.10px**，新缓动约 0.01px。

**7. 书脊与装订缝必须画在纸叶之上。**

页面、书脊、装订缝原本都在同一个书本容器里（书脊 `z-index: 20`、装订缝 `21`），
而纸叶是另一个兄弟容器（`z-index: 40`）—— 于是**纸叶盖住了书脊阴影**：

- 翻页途中，纸叶落在哪一侧，那一侧页面上的书脊阴影就被压掉；
- 落平帧纸叶被卸载，阴影「啪」地又回到页面上。

实测这让「最后一帧 → 落平帧」在页面内侧多出一条**贯穿整页高的竖带差异**
（宽约 22 屏幕px，正好是书脊渐变压在页面上的那一段）——
也就是「书脊这两个地方翻完还是会变一下」。

解法是把书脊与装订缝挪进一个独立的兄弟容器，`z-index: 50`，压在纸叶之上：
它们是**书的凹槽**，不是某一页的内容，任何时刻都该待在同一个位置、压在所有纸之上。
实测整图差异从 **0.36% 降到 0.19%**，且那条竖带不再是主要差异。

验收（`pnpm flip:verify`）：纸叶存在时，书脊层的 `z-index` 必须大于纸叶层。

### 其它

- **可以拖动**：指针横向拖动时纸板跟随手指转动，松手按进度（阈值 35%）
  决定翻过去还是弹回。纸不会自己动，是手指带着它动。
- **双向**：`next` 与 `prev` 各自完整（右侧抬起向左落 / 左侧抬起向右落）。
- **动画中禁止重复触发**：`busyRef` 守卫，连续快速点击不会破坏状态。
- **动态阴影**：纸板抬离时整体压暗（90° 最暗）、中段有掠光扫过、
  并在下方页面投下随进度移动的阴影（抬起增强、落下收敛）。
- **照片预解析**：`usePhotosReady` 在打开阅读器前把所有照片地址解析完。
  纸板正反面各渲染一份内容，若地址未就绪，后挂载的那份会先画成灰色占位图。

## 动效设计

动效的目标不是「加动画」，而是让界面里的东西**遵守它假装拥有的物理规则**：
照片是纸、页面是书板、书是放在桌上的实物。所以每一条动效都能对应到
一个现实中的因果，而不是为了好看而加。

### 通用原则

**旋转容器不能有 `overflow: hidden` / `border-radius` / `filter`**。
这些属性会让元素被强制变成 `transform-style: flat`，子元素的 3D 变换被拍平 ——
表现就是「翻页像被压扁的矩形」而不是在空间里转过去。
裁切必须发生在容器**内部**的元素上。这是本项目踩过的最隐蔽的一个坑。

### 开书入场

目前**没有**封面翻开的入场动画 —— 早先这一节描述的 `easeOutBack` 900ms
在代码里从来没有实现过，已按事实删除。阅读器挂载后直接呈现跨页。

### 减弱动态效果

`prefers-reduced-motion: reduce` 全局生效：所有 CSS 动画与过渡被压缩到近乎瞬时，
阅读器的翻页会直接切换而不是播放 3D 旋转。这不是可选项 ——
前庭功能障碍用户会因为大幅位移与 3D 旋转产生不适，而翻书正是最典型的触发源。

触屏横向滑动在减弱动效下**不会**变成「什么都不发生」：手指一划就立即翻页
（跳过 3D 滑动，只保留结果）。之前 `beginDrag` 直接返回 false 并清空手势状态，
连「快速划动」兜底一起失效，触屏用户在开启减弱动效后完全翻不了页。

### 如何验收动效

两个脚本，都在做**定格**，区别只在定格哪些点：

- `pnpm flip:shots` —— 用 `?flip=next&hold=0.5` 把纸板**定格**在 7 个角度
  （0°~171°）逐一截图，验证单帧几何：3D 有没有被拍平、纸板正反面朝向、是否镜像。
- `node scripts/audit-flip-frames.mjs` —— 用 `?sampleAt=N` 把纸板定格在
  「真实动画第 N 帧**应当**处于的进度」（`easeSettle(N / 总帧数)`），
  覆盖动画时间线上的 12 个点。

> 覆盖边界要说清楚：`?sampleAt` **并不播放动画**，它和 `?flip&hold` 是同一套
> 定格机制，因此验证的是「该进度下渲染了哪几页」，**不验证时序**。
> `settleThenCommit` 的双 rAF 交接、busy 守卫、真实帧间隔目前**没有**自动化覆盖，
> 只能靠 `pnpm flip:verify` 的「落平帧 == 提交后静止帧」几何断言间接约束。

定格用 `useLayoutEffect` 保证在浏览器绘制之前写入角度，截图才能抓到目标帧。
另外 `BookSpread` 上的 `data-left / data-right / data-leaf-front /
data-leaf-back / data-progress / data-landed` 把「这一帧到底渲染了哪几页」
暴露给 DOM，便于自动化断言 —— 一次翻页涉及四处页面，出问题时很难靠肉眼看出来。
（`data-progress` 保留 5 位小数：3 位时 p=0.99997 会打印成 `"1.000"`，
与同时为 `0` 的 `data-landed` 自相矛盾。）

## 未来接入点

### 1. 对象存储（S3）

只需实现 `src/storage/storage.ts` 里的 `StorageAdapter`：

```ts
createS3Storage({
  bucket, region, publicBaseUrl, metadataEndpoint,
  signUpload: (key, contentType) => Promise<{ url, publicUrl }>,  // 后端签发预签名 URL
})
```

接入后 `putAsset` 返回 `publicUrl`，`PhotoAsset.source` 变成 `'remote'`，
`storageKey` 置空 —— **上层代码零改动**（上传管道、素材库、编辑器都只依赖接口）。
`createS3Storage` 已经预留了完整形状，目前故意抛错而不是假装实现。

### 2. AI 自动排版

`src/ai/provider.ts` 定义了 `AiLayoutProvider`：

```ts
analyze(photos)  → PhotoInsight[]                 // 内容类型 / 构图 / 评分 / 是否适合做封面
layout(request)  → { plan, pages, summary }       // 章节 → 页面 → 元素
```

当前实现 `heuristicProvider` 是**完全离线、确定性**的：用文件名、宽高比、
拍摄时间与 EXIF 地点推断内容类型，按内容分章，再调用 `layoutEngine` 排版。
产出的数据结构与真实模型完全一致，因此换成多模态模型时：

- 编辑器、创建流程、UI 进度提示都不需要改；
- 用户依然可以完全手动修改生成结果（这是产品要求）。

替换方式：UI 只通过注册表取实现，不再直接 import 具体 provider。

```ts
// 应用入口（src/main.tsx）注册默认实现
registerDefaultAiProvider(() => heuristicAiProvider)

// 接入真实模型时覆盖即可（例如按后端开关 / 环境变量决定）
setAiProvider(myMultimodalProvider)
```

`layoutEngine` 的版式函数也被编辑器「模板」面板复用，保证模板与自动生成结果同源。

### 3. 真实地图

`MapView` 目前把经纬度做等距圆柱投影后离线绘制手绘路线（不依赖任何地图服务）。
接入真实地图时只需替换 `project()` 这一个函数。

## Demo 数据是怎么来的

`scripts/generate-demo-assets.mjs` 用**纯 Node（无第三方依赖）**程序化生成 26 张照片：

- 手工实现 PNG 编码器（CRC32 + zlib deflate）；
- 先渲染为真彩色，再用**中位切分法量化到 128 色并输出索引色 PNG** ——
  演示图带有胶片颗粒，真彩色几乎无法压缩（每张 1MB+），
  量化后视觉差异几乎不可见，总体积从 28MB 降到 5.5MB；
- 场景由参数描述（天空渐变、多层山脊、水面倒影、瀑布、公路、桌面、人物剪影、
  星空、颗粒与暗角），随机数使用固定种子，**每次生成结果完全一致**。

## 已知限制

- **`pnpm dev` 端口固定 5273**，`strictPort` 已开启；被占用时会直接报错而不是静默换端口。
- `vite.config.ts` 里忽略了 `.dsh-tmp/**`、`**/*.tmpdir/**` 等临时路径：开发工具的
  临时产物（尤其浏览器 profile、以及编辑器写文件时产生的中转目录）会让文件监听器
  抛 `EBUSY` 并拖垮整个 dev server（实测被 `.README.md.*.tmpdir/` 打崩过一次）。
- 无头浏览器环境下 IndexedDB 可能永远不返回。因此启动流程**不阻塞渲染**：
  `libraryStore` 创建时自带一份 demo 纪念册，首帧永远是完整书架，
  存储层的真实数据到齐后再无缝替换。这同时也修掉了「回访用户看启动动画」的体验问题。
  代价是：**深链直接打开编辑器/阅读器**时，用户自己的册子要等存档读完才出现，
  因此这两个页面对「找不到」做了区分 —— 存档未就绪时显示加载态，而不是 404。
- 移动端只保证**查看 / 翻页 / 分享**（编辑器未做移动端适配，符合需求约定）。
- 页面尺寸当前固定为 720×900（4:5）。数据模型已经支持每本册子自定义
  `pageSize`，但编辑器 UI 尚未暴露这个设置。
- `ph_peak_01` / `ph_peak_03` / `ph_night_02` 三张素材已生成但未放进 demo 页面，
  留给用户自己在编辑器里使用（`pnpm check` 会以「提示」而非「错误」的形式列出）。
- **翻页落地时文字仍有约 0.19% 的亚像素重光栅化**（位置完全一致，实测几何差 0.01px）。
  原因：纸叶的背面是 `rotateY(180deg)` 镜像，浏览器在**镜像空间**里光栅化文字，
  于是字形的次像素相位与静止页差一点点 —— 落地时文字会有一次极轻微的重绘。
  已验证**不是**抗锯齿模式切换：强制灰度抗锯齿、以及让静止页也进合成层，
  两种改法都测过，差异纹丝不动。这是「把页面画成 3D 纸板背面」的固有代价。
  作为对照：落平帧与真实静止帧逐像素对比是 **0%**（只差页脚页码）。
- **编辑器不做元素越界裁剪**：元素可以被拖到页面之外，编辑器里照样可见，
  而阅读器与导出会按 `overflow-hidden` 裁掉（所见与所得不一致）。
  拖动/缩放目前没有页面边界 clamp。
- 属性面板的**锁定**只阻止拖动、缩放、删除与属性修改；框选仍会跳过锁定元素，
  但没有「解锁才能选中」这层约束。

## 验证方式

```bash
pnpm check
```

依次执行：

1. **引用一致性校验** —— 扫描所有 `sticker('id')` / `photo('id')` 调用与素材文件，
   确保没有指向不存在的贴纸、照片或缺失的图片文件。
   （这套校验实际抓到了两个写错的贴纸 id：`mapPin`、`travel-luggageTag`，
   它们在运行时会让整个页面白屏，而截图里只表现为「一片黑」。）
2. **单元测试** —— 33 个用例覆盖旋转命中、包围盒、**旋转元素的缩放不变量**、
   边手柄单轴语义、保持比例（含 Alt+Shift 组合）、多选群组缩放、
   拖拽吸附、框选、层级调整。
3. **全量类型检查** —— `tsc -b`，零错误。
   注意这里必须是 `tsc -b`（会连 `tsconfig.node.json` 一起检查）：
   早先 `check` 只跑 `tsc -p tsconfig.app.json`，而 `pnpm build` 用的 `tsc -b`
   因为缺 `@types/node` 直接失败 —— 类型检查「零错误」掩盖了生产构建是坏的。

此外 `pnpm shot <路径> <输出>` 可以对任意页面做无头截图，用于人工确认渲染结果。

翻页相关的验收另有三条命令（都要求 `pnpm dev` 已在 5273 端口运行）：

- **`pnpm flip:verify`** —— 翻页不变量。走 Chrome DevTools Protocol 读真实 DOM 与
  `getBoundingClientRect()`，断言三件事：翻页途中「正在阅读的那一页」全程不变、
  **落平帧与提交后的静止画面逐值一致（含几何）**、静止态没有幽灵翻页。
  「页落下后又动一下」这类问题就靠它判定，不依赖肉眼，也不依赖视觉模型。
- `pnpm flip:frames` —— 把纸板定格在动画时间线的 12 个进度点截图
  （**定格**，不播放动画；它验证不了时序，理由见上一节）。
- `pnpm flip:shots` —— 把纸板定格在若干角度截图，验证单帧几何。

> 注意：读几何之前必须等布局稳定。`BookViewport` 的尺寸带 0.4s 过渡，
> 而外层用 `items-center` 居中 —— 容器在过渡时书本的垂直位置本来就在动。
> 若「元素一出现就读」，会把过渡中间态当成真实位移（实测两次读数能差出 64px）。
> `flip:verify` 因此要求连续两次采样（间隔 250ms）几何完全一致才认账。

### 最近修掉的几处硬伤

以下都是「文档说做到了、代码其实没做到」或者会直接毁掉核心体验的问题：

| 问题 | 症状 | 根因与修法 |
| --- | --- | --- |
| 自动保存清空撤销栈 | 编辑约 900ms 后撤销按钮变灰、属性面板清空、画布跳回第 1 页 | 保存回写 library 改变了对象引用，触发了「重新载入」effect。改为只在切换册子时载入 |
| 右页元素无法编辑 | 跨页布局里右页元素拖动毫无反应、删不掉却提示成功 | 写操作只认 `activePageId`（永远是左槽）。改为按元素 id 反查所在页 |
| 旋转元素缩放跳变 | 指针一动不动，旋转 90° 的 200×100 元素变成 150×150、锚点漂 50px | 把旋转后的 AABB 当成元素矩形用。改为先还原本地矩形，再补偿旋转 |
| `pnpm build` 失败 | `Cannot find type definition file for 'node'` | `tsconfig.node.json` 声明了 `types: ["node"]` 却没有 `@types/node`；`check` 又只跑 app 项目所以没暴露 |
| `pnpm test` 跑不起来 | Node 22.15 下 `Unknown file extension ".ts"` | 测试脚本缺 `--experimental-strip-types` |
| 翻页验收有假断言 | 「书口不得凸出」永远通过 | 断言查的 `data-stack` 全项目没有生产者 |
| 阅读页书名被压住 | 浮动工具栏盖住标题第一个字 | Reader 顶部信息块与浮层同处 `left-5 top-5`，改为由外层传入让位距离 |
| 删除照片留下死引用 | 册子里的照片变成灰底占位，且没有任何提示 | 删除素材时没有级联清理 `photoId` 引用；现在会清理并如实报告影响了几本册子 |
| 属性面板灌爆历史 | 拖一次滑块就吃掉几十步撤销 | 每次 pointermove 都 `commit`。改为事务化：一段调整只留一条历史 |
